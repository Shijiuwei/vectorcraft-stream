Localization parity

Last reviewed: 2026-10-10 · Last updated: 2026-10-23 · Change: patch (missing translations never fail; cargo xtask ci prints the untranslated report)

Per-language status of VectorCraft's interface. How the catalogs work and how to add a language: development.md › Localisation. Part of target-app-parity.md.

How it is measured: rows with a translation in each crates/ui-egui/src/i18n/<code>.tsv, counted on origin/main 01e165af, except the rows that give a count date, which were counted on main at cb0a7d9 (2026-10-21). The reference is the French catalog, which was complete when counted: 3,416 interface strings (menus, command labels, tl! literals: panels, dialogs, tooltips, Preferences) plus 604 @msg status and error messages, 4,020 in all. A language's % is its rows over 4,020 (capped at 100% per part). A missing translation never fails a test or a build: the interface shows the English text until a translator adds the row. cargo xtask ci prints the untranslated report (cargo xtask i18n-report alone), which lists per language the strings missing from each catalog with the complete_menus flag and the messages missing from each language in the COMPLETE_MESSAGES list. Every non-English language marked "full" has the flag, and all of them except Bulgarian, Danish, Indonesian and Dutch are in the list. No language has help content: there is no translated (or English) in-app help, and the docs are English.

Native review: every catalog was written clean-room from the English meaning, most of it by agents (bflatastic), with community contributors adding or correcting (German by dwetscher, Japanese and Traditional Chinese by imachus). Only Georgian is recorded as reviewed by a native speaker; the other catalog headers ask for one.

Czech render-site follow-up

The desktop and web file pickers look up filter labels at assignment time; format names and extensions stay unchanged. Diagnostics retain numeric values and units. New Document's suggested preset name uses Preset {number}. Contributor tooltips use named placeholders and Czech plurals; handles and chosen names remain unchanged. Gradient descriptions reuse {kind} Gradient with a contextual radial adjective. PDF/Print mark styles use mark-style, so Japanese displays as Japonské while the language name stays Japonština; their Summary uses the same context.

The search placeholder, Home screen, toolbar/panel tooltips and Preferences already use lookups. No new tl!("literal") keys were needed: only cs.tsv adds 19 AI-draft rows and revises the gradient template. Every other complete catalog (complete_menus) has the same rows and a Roman row for the other mark style; the untranslated report lists a catalog that lacks one of them. Native review is still needed, and catalog coverage does not prove that every variable in the UI is translated.

Not done in any language

Locale-aware number and date formats, a right-to-left interface, translated help, and a Traditional Chinese UI font for the web build.
